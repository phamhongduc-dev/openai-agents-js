Tool cho phép Agent **thực hiện hành động** – lấy dữ liệu, gọi API bên ngoài, chạy code, hoặc thậm chí dùng computer. JavaScript/TypeScript SDK hỗ trợ sáu loại:

> Đọc trang này sau [Agent](/vi/guides/agents) khi bạn biết agent nào nên sở hữu tác vụ và muốn cung cấp khả năng cho nó.

1. **Hosted OpenAI tool** – chạy cùng model trên server OpenAI. _(web search, file search, code interpreter, image generation, tool search)_
2. **Built-in execution tool** – tool SDK cung cấp sẵn chạy bên ngoài model. _(computer use và apply_patch chạy local; shell có thể chạy local hoặc trong hosted container)_
3. **Function tool** – bọc bất kỳ hàm local nào với JSON schema để LLM có thể gọi.
4. **Agent dùng như tool** – expose toàn bộ Agent như tool có thể gọi.
5. **MCP server** – gắn server Model Context Protocol (local hoặc remote).
6. **Thử nghiệm: Codex tool** – bọc Codex SDK như function tool để chạy tác vụ workspace-aware.

## Các loại tool

### 1. Hosted tool (OpenAI Responses API)

Khi dùng `OpenAIResponsesModel` bạn có thể thêm các built-in tool sau:

| Tool | Type string | Mục đích |
| --- | --- | --- |
| Web search | `'web_search'` | Tìm kiếm Internet. |
| File / retrieval search | `'file_search'` | Query vector store trên OpenAI. |
| Code Interpreter | `'code_interpreter'` | Chạy code trong sandbox. |
| Image generation | `'image_generation'` | Sinh ảnh từ text. |
| Tool search | `'tool_search'` | Tải deferred function tool, namespace, hoặc searchable MCP tool lúc runtime. |

#### Tham khảo tùy chọn

| Field | Bắt buộc | Mô tả |
| --- | --- | --- |
| `name` | Không | Mặc định là tên hàm. |
| `description` | Có | Mô tả rõ ràng cho LLM. |
| `parameters` | Có | Zod schema hoặc raw JSON schema. |
| `strict` | Không | Khi `true` (mặc định), SDK trả lỗi model nếu tham số không validate. |
| `execute` | Có | Logic nghiệp vụ. |
| `needsApproval` | Không | Yêu cầu phê duyệt trước khi thực thi. |
| `isEnabled` | Không | Expose tool có điều kiện theo lần chạy. |
| `timeoutMs` | Không | Timeout cho mỗi lần gọi. |

## Chiến lược tool và best practice

- **Mô tả ngắn, rõ ràng** – mô tả tool làm _gì_ và _khi nào dùng_.
- **Validate input** – dùng Zod schema cho strict JSON validation.
- **Tránh side-effect trong error handler** – `errorFunction` nên trả string hữu ích, không throw.
- **Một trách nhiệm mỗi tool** – tool nhỏ, có thể kết hợp dẫn đến suy luận model tốt hơn.
