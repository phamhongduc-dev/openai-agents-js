Agent là khối xây dựng chính của OpenAI Agents SDK. Một **Agent** là một Large Language Model (LLM) đã được cấu hình với:

- **Instruction** – system prompt cho model biết _nó là ai_ và _nên phản hồi như thế nào_.
- **Model** – model OpenAI nào sẽ được gọi, cùng với các tham số tinh chỉnh model tùy chọn.
- **Tool** – danh sách các hàm hoặc API mà LLM có thể gọi để hoàn thành tác vụ.

## Nền tảng Agent

### Cấu hình cơ bản

Constructor `Agent` nhận một object cấu hình duy nhất. Các property thường dùng nhất được hiển thị bên dưới.

| Property | Bắt buộc | Mô tả |
| --- | --- | --- |
| `name` | có | Định danh ngắn, dễ đọc. |
| `instructions` | có | System prompt (string **hoặc** function – xem [Dynamic instruction](#dynamic-instructions)). |
| `prompt` | không | Cấu hình prompt OpenAI Responses API. Chấp nhận object prompt tĩnh hoặc function. Xem [Prompt](/vi/guides/models#prompt). |
| `handoffDescription` | không | Mô tả ngắn được dùng khi agent này được cung cấp như một handoff tool. |
| `handoffs` | không | Ủy quyền cuộc hội thoại cho agent chuyên biệt. Xem [Mẫu kết hợp](#composition-patterns) và [hướng dẫn Handoff](/vi/guides/handoffs). |
| `model` | không | Tên model **hoặc** implement [`Model`](/openai-agents-js/openai/agents/interfaces/model/) tùy chỉnh. |
| `modelSettings` | không | Tham số tinh chỉnh (temperature, top_p, v.v.). Xem [Model](/vi/guides/models#modelsettings). Nếu property cần không có ở cấp cao nhất, bạn có thể đưa vào `providerData`. |
| `tools` | không | Mảng các instance [`Tool`](/openai-agents-js/openai/agents/type-aliases/tool/) mà model có thể gọi. Xem [Tool](/vi/guides/tools). |
| `mcpServers` | không | Tool hỗ trợ MCP cho agent. Xem [hướng dẫn MCP](/vi/guides/mcp). |
| `inputGuardrails` | không | Guardrail áp dụng cho user input đầu tiên trong chuỗi agent. Xem [Guardrail](/vi/guides/guardrails). |
| `outputGuardrails` | không | Guardrail áp dụng cho output cuối cùng của agent này. Xem [Guardrail](/vi/guides/guardrails). |
| `outputType` | không | Trả về structured output thay vì plain text. Xem [Output type](#output-types) và [Kết quả](/vi/guides/results#final-output). |
| `toolUseBehavior` | không | Kiểm soát liệu kết quả function-tool có quay lại model hay kết thúc lần chạy. Xem [Ép dùng tool](#forcing-tool-use). |
| `resetToolChoice` | không | Reset `toolChoice` về mặc định sau khi gọi tool (mặc định: `true`) để tránh vòng lặp dùng tool. Xem [Ép dùng tool](#forcing-tool-use). |
| `handoffOutputTypeWarningEnabled` | không | Phát cảnh báo khi output type của handoff khác nhau (mặc định: `true`). Xem [Kết quả](/vi/guides/results#final-output). |

1. [Zod](https://github.com/colinhacks/zod) schema (`z.object({...})`).

### Ánh xạ với OpenAI platform

Một số khái niệm agent ánh xạ trực tiếp sang khái niệm OpenAI platform, trong khi một số khác được cấu hình khi bạn chạy agent thay vì khi định nghĩa nó.

| Khái niệm SDK | Hướng dẫn OpenAI | Khi nào quan trọng |
| --- | --- | --- |
| `outputType` | [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) | Agent cần trả về JSON có kiểu hoặc object đã validate bằng Zod thay vì text. |
| `tools` / hosted tool | [Hướng dẫn Tool](https://developers.openai.com/api/docs/guides/tools) | Model cần tìm kiếm, truy xuất, chạy code, hoặc gọi function/tool của bạn. |
| `conversationId` / `previousResponseId` | [Trạng thái cuộc hội thoại](https://developers.openai.com/api/docs/guides/conversation-state) | Bạn muốn OpenAI duy trì hoặc nối chuỗi trạng thái hội thoại giữa các lượt. |

`conversationId` và `previousResponseId` là điều khiển runtime, không phải field của constructor `Agent`. Dùng [Chạy Agent](/vi/guides/running-agents) khi cần các entry point SDK đó.

## Mẫu kết hợp

Hai entry point SDK xuất hiện thường xuyên nhất khi agent tham gia một workflow lớn hơn:

1. **Manager (agent dùng như tool)** – một agent trung tâm sở hữu cuộc hội thoại và gọi các agent chuyên biệt được expose như tool.
2. **Handoff** – agent ban đầu ủy quyền toàn bộ cuộc hội thoại cho agent chuyên biệt khi đã xác định được yêu cầu người dùng.

Các cách tiếp cận này bổ trợ nhau. Manager cho bạn một nơi duy nhất để áp dụng guardrail hoặc rate limit, trong khi handoff cho phép mỗi agent tập trung vào một tác vụ mà không cần giữ quyền kiểm soát cuộc hội thoại. Để biết các đánh đổi thiết kế và khi nào chọn mẫu nào, xem [Điều phối Agent](/vi/guides/multi-agent).

#### Manager (agent dùng như tool)

Trong mẫu này, manager không bao giờ chuyển giao quyền kiểm soát — LLM dùng tool và manager tổng hợp câu trả lời cuối cùng. Đọc thêm trong [hướng dẫn Tool](/vi/guides/tools#agents-as-tools).

### Lifecycle hook

Cho các use case nâng cao, bạn có thể quan sát lifecycle Agent bằng cách lắng nghe event.

Instance `Agent` emit lifecycle event cho agent cụ thể đó, trong khi `Runner` emit cùng tên event như một stream duy nhất xuyên suốt toàn bộ lần chạy. Điều này hữu ích cho workflow đa agent khi bạn muốn một nơi để quan sát handoff và lệnh gọi tool.

Các tên event dùng chung:

| Event | Tham số hook Agent | Tham số hook Runner |
| --- | --- | --- |
| `agent_start` | `(context, agent, turnInput?)` | `(context, agent, turnInput?)` |
| `agent_end` | `(context, output)` | `(context, agent, output)` |
| `agent_handoff` | `(context, nextAgent)` | `(context, fromAgent, toAgent)` |
| `agent_tool_start` | `(context, tool, { toolCall })` | `(context, agent, tool, { toolCall })` |
| `agent_tool_end` | `(context, tool, result, { toolCall })` | `(context, agent, tool, result, { toolCall })` |

### Ép dùng tool

Cung cấp tool không đảm bảo LLM sẽ gọi. Bạn có thể **ép** dùng tool bằng `modelSettings.toolChoice`:

1. `'auto'` (mặc định) – LLM quyết định có dùng tool hay không.
2. `'required'` – LLM _phải_ gọi tool (có thể chọn tool nào).
3. `'none'` – LLM **không được** gọi tool.
4. Tên tool cụ thể, ví dụ `'calculator'` – LLM phải gọi tool cụ thể đó.

Khi tool có sẵn là `computerTool()` trên OpenAI Responses, `toolChoice: 'computer'` đặc biệt: nó ép dùng built-in computer tool GA thay vì xử lý `'computer'` như tên function thông thường. SDK cũng chấp nhận preview-compatible computer selector cho các tích hợp cũ hơn, nhưng code mới nên ưu tiên `'computer'`. Nếu không có computer tool, string hoạt động giống tên function tool bất kỳ.

<Code lang="typescript" code={agentForcingToolUse} title="Ép dùng tool" />

Khi bạn dùng deferred Responses tool như `toolNamespace()`, function tool với `deferLoading: true`, hoặc hosted MCP tool với `deferLoading: true`, hãy giữ `modelSettings.toolChoice` ở `'auto'`. SDK từ chối ép dùng deferred tool hoặc helper built-in `tool_search` theo tên vì model cần quyết định khi nào tải các định nghĩa đó. Xem [hướng dẫn Tool](/vi/guides/tools#deferred-tool-loading-with-tool-search) để biết thiết lập đầy đủ.

#### Ngăn vòng lặp vô hạn

Sau khi gọi tool, SDK tự động reset `toolChoice` về `'auto'`. Điều này ngăn model rơi vào vòng lặp vô hạn khi liên tục cố gọi tool. Bạn có thể ghi đè hành vi này qua cờ `resetToolChoice` hoặc bằng cách cấu hình `toolUseBehavior`:

- `'run_llm_again'` (mặc định) – chạy LLM lại với kết quả tool.
- `'stop_on_first_tool'` – xử lý kết quả tool đầu tiên như câu trả lời cuối.
- `{ stopAtToolNames: ['my_tool'] }` – dừng khi bất kỳ tool nào trong danh sách được gọi.
- `(context, toolResults) => ...` – function tùy chỉnh trả về liệu lần chạy có nên kết thúc.

```typescript
const agent = new Agent({
  ...,
  toolUseBehavior: 'stop_on_first_tool',
});
```

Lưu ý: `toolUseBehavior` chỉ áp dụng cho **function tool**. Hosted tool luôn trả về model để xử lý.
